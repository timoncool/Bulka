## Tips and tricks

### Common mistakes

**`n` vs `note`: what's the difference?**

- `note` changes the pitch
- `n` picks a sample number from the bank

<MiniRepl
  client:visible
  tune={`// n picks a sample from the bank
s("bd").n("<0 1 2 3>")  // different kicks`}
/>

<MiniRepl
  client:visible
  tune={`// note changes the pitch
s("piano").note("c4 e4 g4 c5")`}
/>

With synths both change the pitch, but with samples `n` picks the file!

**The Reference panel slows things down**

If things get sluggish, close the Reference panel. It renders many elements and can affect audio performance.

**Sounds don't load the first time**

Samples have to load, so the first run may be silent. Just run the code again.

### Workflow tips

**Use the Community Bakery for inspiration**

Open [strudel.cc/bakery](https://strudel.cc/bakery/) and study other people's patterns: it's the best way to learn new techniques.

**Share your code**

Press the "share" button in the REPL to get a link to your pattern that you can share.

**Don't be afraid to delete code**

If you don't like the result, delete it and start over. That's a normal part of live coding.

## Example tracks

### Minimal techno

<MiniRepl
  client:visible
  tune={`// A minimal techno groove
stack(
  s("bd*4").gain(1.2),
  s("~ cp").room(0.3),
  s("hh*8").gain(0.6).pan(sine.range(0.3, 0.7)),
  note("g1*2 [~ g1] g1 [g1 a1]")
    .s("sawtooth")
    .lpf(sine.slow(8).range(200, 1200))
    .lpq(8)
    .gain(0.7)
)`}
/>

### Ambient drone

<MiniRepl
  client:visible
  tune={`// Atmospheric ambient
stack(

    .s("sawtooth")
    .lpf(400)
    .attack(2)
    .release(4)
    .room(0.8)
    .size(0.9)
    .slow(4),
  note("c2").s("sine")
    .gain(0.3)
    .slow(8)
)`}
/>

## Advanced techniques

### Breakbeat chopping

<MiniRepl
  client:visible
  tune={`// A classic amen break chop
samples('github:yaxu/clean-breaks')
s("amen/4").fit()
  .chop(16)
  .cut(1)
  .sometimesBy(0.3, ply(2))
  .sometimesBy(0.2, rev)`}
/>

### Generative patterns with rand

<MiniRepl
  client:visible
  tune={`// Random variations
note("c3 e3 g3 b3")
  .add(note(rand.range(-2, 2)))
  .s("piano")
  .sometimesBy(0.3, add(note(12)))`}
/>

### Layer for complex textures

<MiniRepl
  client:visible
  tune={`// Stacking different processing
note("c3 e3 g3 b3").layer(
  x => x.s("sawtooth").lpf(800),
  x => x.s("square").add(note(12)).gain(0.3),
  x => x.s("sine").sub(note(12)).gain(0.5)
).room(0.5)`}
/>

### Phasing

<MiniRepl
  client:visible
  tune={`// Steve Reich style phasing
note("c4 d4 e4 g4 a4 g4 e4 d4")
  .s("piano")
  .fast("[1, 1.01]")  // slightly different speeds
  .room(0.4)`}
/>

### Conditional modifiers

<MiniRepl
  client:visible
  tune={`// Apply an effect every N cycles
s("bd sd cp sd")
  .every(4, fast(2))
  .every(3, rev)
  .sometimesBy(0.2, speed(1.5))`}
/>

## Performance

- **Close the Reference panel** while live coding
- **Use `.cut(1)`** on samples to avoid overlaps
- **[Desktop app](/learn/desktop)** — Bulka without a browser, for Windows, Linux and macOS
- **Go easy on reverb** — high `.room()` and `.size()` values load the CPU

## The live coding philosophy

> "Don't be afraid of mistakes: they are part of the process. Practice like on a musical instrument. It gets better with time."

Live coding is:
- **Experiment** — try different things and listen to what happens
- **Process** — the path matters, not only the result
- **Community** — share, learn from others, ask questions
